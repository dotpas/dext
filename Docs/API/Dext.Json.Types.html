function MaxDepth: Integer
Returns the effective maximum depth limit. Defaults to 64 if not set.
function ZeroDateAsNull(AValue: Boolean): TJsonSettings
A TDateTime or TDate that is 0 (1899-12-30, "no date") is written as null instead of "1899-12-30T00:00:00.000" (dropped with IgnoreNullValues), on every path: class properties, record fields, array elements, single values. A TTime is left alone: 0 is midnight there. On by default; ZeroDateAsNull(False) writes the zero date.
function NullDates(const const: array): TJsonSettings
The dates that mean "no date" for this application, as 'yyyy-mm-dd' (for example '0001-01-01' and '1900-01-01', the values legacy databases and NOT NULL columns use): written as null like the zero date, on every path, and dropped with IgnoreNullValues. A value is "no date" when it is exactly that day: a sentinel has no time, so '1900-01-01 08:30' is still a date. A TTime is left alone. The list replaces the previous one; an empty list turns it off (the default). Reading is not affected. A text that is not a valid day raises EConvertError.
function IsNullDate(const const: TDateTime): Boolean
True when AValue is one of the NullDates.
function KeepDefaultEnums(AValue: Boolean): TJsonSettings
With IgnoreDefaultValues, an enum at its first value (ordinal 0) is still written: that value is often a business state ("Draft", "Active") that a consumer must see. A False Boolean is still dropped.
function BytesAsBase64(AValue: Boolean): TJsonSettings
A byte array (TBytes, or any dynamic array of Byte) is written as a Base64 string on one line, with padding (RFC 4648, OpenAPI "format: byte"). It is the default; False writes it as an array of numbers, as before. Reading accepts both, whatever this setting.
